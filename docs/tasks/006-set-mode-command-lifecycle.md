# 006 — 模式切换命令闭环

## 目标

实现Windows地面站到ROS车辆控制层的第一条有副作用命令，并完整区分命令已发送、网关已接受、车辆已执行、执行失败、本地超时和断线后结果未知。

## 本次范围

- 地面站发送V1 `command/set_mode`。
- 网关声明`set_mode`能力并验证请求。
- 网关将合法请求串行转发给现有ROS模式管理器。
- 网关等待`/control/mode`实际反馈后返回最终`ack`。
- 地面站显示模式操作按钮、确认对话框和命令状态。
- 记录命令生命周期日志，使用`request_id`关联。
- 覆盖协议、重复请求、超时、断线和WebSocket闭环测试。

## 不在本次范围

- 人工速度、停止、急停和解除急停命令。
- 导航、任务取消、地图和路径。
- 自动重发任何模式切换命令。
- 直接由Qt连接ROS2。
- Jazzy分支适配。

## 关键规则

1. Qt按钮不能直接改变实际模式；`VehicleState.mode`仅由车辆遥测更新。
2. `accepted`不代表执行完成；网关必须等到实际模式反馈匹配才返回`completed`。
3. 网关执行窗口为2秒，地面站本地最终结果等待窗口为3秒。
4. 模式命令在ROS端串行执行，不为每条命令创建线程。
5. 完全相同的重复`request_id`返回缓存应答，不重复执行；内容冲突则拒绝。
6. 连接断开时未完成命令变为“结果未知”，重连后不得自动重发。
7. 网关未在`gateway_ready.capabilities`声明`set_mode`时，界面禁用模式切换。

## 验收

- RC、AUTO和GROUND按钮仅在车辆在线、网关支持且没有待处理命令时可用。
- 操作前显示确认对话框。
- 正常流程可观察到`sent → accepted → completed`。
- ROS实际模式未变化时最终为`failed/mode_change_timeout`。
- 非法模式和冲突重复请求不会执行。
- 断线和本地超时不会触发自动重发。
- Windows Qt测试及ROS网关纯Python测试通过；ROS构建与Topic联调在Ubuntu Humble完成。
