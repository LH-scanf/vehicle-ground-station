# Qt 无人车地面站技术要求

***\*文档版本：\**** V0.1
***\*项目阶段：\**** 需求与技术选型阶段
***\*目标平台：\**** Windows 10 / Windows 11
***\*开发框架：\**** Qt 6
***\*适用对象：\**** ROS2 无人车仿真平台及后续实车平台



------



## 1. 项目概述

本项目拟开发一套运行于 Windows 平台的无人车地面站软件。

地面站通过网络与运行在 Linux 或车载计算机上的 ROS2 系统连接，实现车辆运行状态监控、二维地图显示、目标点下发、任务管理、控制模式切换、远程控制、异常告警及日志记录等功能。

地面站主要面向无人车操作人员和项目开发人员使用。

本项目不替代 RViz 和 Foxglove。

RViz 和 Foxglove继续用于 ROS2 节点、Topic、TF、激光雷达、点云和算法数据的开发调试；Qt 地面站主要用于车辆操作、任务执行和状态监控。



------



## 2. 建设目标

地面站应达到以下目标：

\1. 可在 Windows 系统独立运行。

\2. 可通过局域网连接 ROS2 无人车。

\3. 可实时显示车辆位置、速度、航向、电量和运行模式。

\4. 可显示 ROS2 生成的二维栅格地图。

\5. 可在地图上显示车辆当前位置、朝向和运动轨迹。

\6. 可通过点击地图向车辆发送导航目标点。

\7. 可切换遥控、自动驾驶和地面站控制模式。

\8. 可执行急停、暂停和取消任务操作。

\9. 可记录车辆状态、操作命令、异常和通信日志。

\10. 后续可扩展多航点任务、GPS地图、电子围栏和实车接入功能。

### 5.3 选择 Qt、C++ 和 QML 的原因

\1. 用户已有 C++ 和 Qt 开发基础。

\2. Qt支持Windows和Linux跨平台运行。

\3. QML适合开发仪表盘、地图和动态状态界面。

\4. C++适合实现通信、协议解析、状态管理和地图数据处理。

\5. Qt可直接提供WebSocket、数据库、绘图和多线程功能。

\6. 后续可将软件部署给不具备ROS开发环境的操作人员。

## 6. 软件模块划分

地面站软件建议划分为以下模块。

### 6.1 ConnectionManager

负责车辆连接管理。

主要功能：

· 设置车辆IP和端口。

· 建立WebSocket连接。

· 主动断开连接。

· 自动重连。

· 连接超时检测。

· 心跳发送。

· 心跳应答检测。

· 通信延迟统计。

· 数据接收频率统计。

· 连接状态通知。

连接状态至少包括：

未连接
连接中
已连接
重连中
连接失败
通信超时



------



### 6.2 VehicleStateManager

负责保存和更新当前车辆状态。

至少包含以下数据：

· 车辆编号。

· 在线状态。

· 当前控制模式。

· 当前任务状态。

· 位置坐标。

· 经纬度。

· 航向角。

· 当前速度。

· 目标速度。

· 当前转向值。

· 当前油门值。

· 电池电压。

· 电池百分比。

· GPS定位状态。

· 遥控器连接状态。

· 通信信号强度。

· 当前航点序号。

· 航点总数。

· 距离下一航点距离。

· 急停状态。

· 通信超时状态。

· 错误码。

· 最后一次状态更新时间。

车辆状态应通过 Qt 的属性机制向 QML 界面提供。



------



### 6.3 MapManager

负责二维地图数据的接收、解析和显示。

主要功能：

· 接收二维栅格地图。

· 解析地图宽度和高度。

· 解析地图分辨率。

· 解析地图原点。

· 将占据栅格转换为界面图像。

· 完成世界坐标与屏幕坐标转换。

· 显示车辆位置。

· 显示车辆朝向。

· 显示全局规划路径。

· 显示车辆历史轨迹。

· 支持地图缩放。

· 支持地图拖动。

· 支持地图复位。

· 支持点击地图设置目标点。

地图应区分：

· 未知区域。

· 可通行区域。

· 障碍区域。

· 车辆位置。

· 目标位置。

· 全局规划路径。

· 已行驶轨迹。



------



### 6.4 MissionManager

负责导航任务管理。

第一阶段主要支持单目标点任务。

主要功能：

· 接收用户在地图上选择的目标点。

· 设置目标朝向。

· 发送导航目标。

· 接收车辆应答。

· 显示任务执行状态。

· 暂停任务。

· 继续任务。

· 取消任务。

· 清除目标点。

· 保存任务执行结果。

任务状态至少包括：

空闲
等待车辆确认
正在执行
已暂停
执行完成
执行失败
已取消
通信中断

第二阶段可扩展：

· 多航点编辑。

支持的控制模式：

## 8. 通信要求

### 8.1 通信方式

地面站与车辆端使用WebSocket长连接通信。

车辆端作为WebSocket服务端，地面站作为客户端。

WebSocket负责：

· 遥测状态上报。

· 地图数据传输。

· 路径数据传输。

· 控制命令下发。

· 任务命令下发。

· 命令应答。

· 心跳检测。

### 8.2 消息编码

普通状态和命令使用UTF-8 JSON。

地图等数据量较大的内容，第一阶段可暂时使用JSON数组；后续根据传输性能切换为二进制协议或压缩数据。

### 8.3 消息统一格式

所有JSON消息应包含统一消息头。

{
 "version": 1,
 "type": "telemetry",
 "name": "vehicle_status",
 "vehicle_id": "car_01",
 "seq": 1001,
 "timestamp": 1784651000123,
 "data": {}
}

字段说明：

| 字段       | 说明             |
| ---------- | ---------------- |
| version    | 协议版本         |
| type       | 消息类型         |
| name       | 具体消息名称     |
| vehicle_id | 车辆编号         |
| seq        | 消息序号         |
| timestamp  | 时间戳，单位毫秒 |
| data       | 消息数据         |

### 8.4 消息类型

建议定义以下消息类型：

telemetry  遥测数据
command   地面站命令
ack     命令应答
event    状态事件
alarm    告警消息
map     地图数据
path     路径数据
heartbeat  心跳消息

### 8.6 命令消息

{
 "version": 1,
 "type": "command",
 "name": "set_mode",
 "vehicle_id": "car_01",
 "request_id": "cmd_1002",
 "timestamp": 1784651000200,
 "data": {
  "mode": "ground"
 }
}

### 8.7 命令应答

所有重要命令必须由车辆返回应答。

{
 "version": 1,
 "type": "ack",
 "name": "set_mode",
 "vehicle_id": "car_01",
 "request_id": "cmd_1002",
 "timestamp": 1784651000250,
 "data": {
  "success": **true**,
  "message": "mode changed to ground"
 }
}

地面站不能将“命令已发送”直接视为“命令执行成功”。

/map

/vehicle_status

根据项目实际Topic名称可进行配置。

### 9.2 车辆网关发布

/cmd_vel

### 9.3 导航接口

地面站发送目标点后，车辆网关应调用Nav2的导航Action。

· 地图分辨率。

· 地图原点位置。

· 地图原点朝向。

· 栅格数据。

· 地图坐标系名称。

· 数据时间戳。

## 10. 安全要求

### 10.1 控制模式安全

车辆只有处于 ground 模式时，地面站才允许发送人工运动控制命令。

地面站必须以车辆实际上报模式为准，不能只根据本地按钮状态判断。

### 10.2 控制超时

地面站人工控制期间，应周期性发送控制命令。

车辆端若超过规定时间未收到控制命令，应自动执行：

· 速度置零。

· 油门置零。

· 停止运动。

· 上报通信超时。

建议初始控制超时时间为500毫秒，后续根据实车测试调整。

### 10.3 急停

急停按钮应始终可见。

急停命令应具有最高优先级。

急停激活后：

· 禁止普通运动控制。

· 禁止开始导航任务。

· 明确显示急停状态。

· 记录急停操作日志。

解除急停必须由操作人员主动执行，禁止自动解除。

### 10.4 断开连接处理

地面站检测到连接断开后应：

· 停止发送普通控制命令。

· 显示车辆离线。

· 禁用任务和人工控制按钮。

· 记录断开时间。

· 尝试自动重连。

车辆端应独立完成通信失联保护，不能依赖地面站发送停车命令。

### 10.5 命令防重复

具有执行副作用的命令应携带唯一 request_id。

车辆端应避免同一 request_id 被重复执行。

· 端口号错误。

· 车辆端无法连接。

· 消息字段缺失。

· 数据更新时间异常。

· 本地日志目录不可写。

· 配置文件损坏。

异常不得直接导致地面站程序退出。

## 18. 当前结论

本项目采用独立Qt地面站方案。

Foxglove继续作为ROS2数据分析和调试工具，不作为正式车辆操作地面站。

第一阶段以“连接车辆、状态显示、二维地图、单点导航、模式切换、急停和日志”为主要目标，不在初期加入多车辆、视频、云端和复杂任务等功能。

开发工作应优先确保通信稳定、车辆安全和核心流程可用，再逐步增加界面效果和扩展功能。
